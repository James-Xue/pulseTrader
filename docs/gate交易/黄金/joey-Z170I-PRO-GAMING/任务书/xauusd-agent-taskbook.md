### 🔌 MCP 故障时的 nc 直连回退通道（2026-08-17 复盘新增）
- **触发条件**：MCP 工具连续 2 次报 9104（broken pipe / EOF）→ 立即切换 nc 通道，不要等 MCP 自愈（桥不会自动重连）
- **方法**：`printf '{"jsonrpc":"2.0","method":"<方法名>","params":{...},"id":1}\n' | timeout 10 nc -w 5 127.0.0.1 8081`
- 方法名与 MCP 工具一一对应（get_status / get_signals / get_positions / get_risk / get_account / get_market / get_orders / open_order / close_position / modify_sl_tp / cancel_order / list_strategies），参数名与 MCP 工具 schema 完全一致（open_order 带 symbol/side/quantity/type/market_type/sl_price/tp_price）。⚠️ get_market 的 kline 参数名为 `klines`（整型，取最近 N 根 1m；JsonRpcServer.cpp:438 实证，2026-08-19 回合392 上报）
- 响应为一行 JSON（`{"id":1,"jsonrpc":"2.0","result":{...}}`），解析方式与 MCP 返回一致；交易方法（open_order/close_position/modify_sl_tp）同样经此通道生效，权限不变
- 每轮开头先试 1 次 MCP，失败即转 nc；nc 连续 3 轮失败才视为引擎不可达，降级监控并记录
- 两种通道交替使用不影响纪律与风控（风控在引擎侧强制执行）
