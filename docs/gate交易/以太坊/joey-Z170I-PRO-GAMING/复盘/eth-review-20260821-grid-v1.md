## 四、教训(升级输入)

### 做对的(保持)
- TP 循环重挂、事件窗口纪律、保护线记账、日亏停手、零打扰用户 —— 机械层全程零失误
- TP 已实现按 fill_price 核算(而非挂单价),+5.0 vs 简算 +2.2 的修正方向正确

### 做错的/边界(要改)
1. **无趋势闸门(致命)**:网格只在现价上方挂空,上涨趋势中=接飞刀。应有 gating:趋势多头/暴拉期间禁挂新格、只管理存量。
2. **保护线 A 对秒级暴冲无反应时间**:15m 收盘判定 + 限价单,2 分钟 +98 点完全穿透。需要更快的检测维度(1m 涨幅/ATR 突变)或接受为固有成本。
3. **9103 名义闸配置缺失**:futures 预算 6000 按"闪迪 + 余量"算,没加 ETH 网格名义(~5247+);且 reduce-only 买单也按新增名义计、不抵扣 → 循环冻结、四格裸奔。引擎配置层问题,可修。
4. **仓位合并连带**:期货单向持仓模式下网格份额与用户仓合并,用户市价单会连带清掉网格 —— 结构性问题,网格无法独立于用户动作运营。缓解:子账户隔离,或网格只在用户不活跃时段/币种运行。
5. **幽灵仓清理**:sync 对空 exchange_position_id 的仓无能为力 → 虚高 PnL、误导判断。
6. **日亏口径未拍板**(UTC 日 08:00 vs 北京日 00:00 重置);step 固定 5 vs ATR 自适应(深夜 ATR 3.44 时 step=3 更优)未拍板。

## 五、升级建议(供拍板)

1. **趋势闸门**:挂格前置条件 = 15m EMA 空头排列(或 EthScalper bearish 信号),多头排列禁挂新格、存量只走 TP/保护线;
2. **暴拉检测**:1m 涨幅 > k×ATR15m 或 > 固定 %(如 1%)→ 冻结新格挂单 X 分钟,存量 TP 照常;
3. **保护线 A 前置**:顶 + 4×step 下移至顶 + 2×step,并加入 1m 收盘超线即触发;
4. **9103 修复**:trading.toml futures 预算按「闪迪 + ETH 峰值名义 + 余量」重算(6000→12000+,maxSymbolNotional 5500→6500),reduce-only 不计名义(引擎侧);
5. **幽灵仓**:sync 剪枝增加「空 exchange_position_id 且交易所无对应仓 → 清理」分支;
6. **日亏口径**:拍板北京日 08:00 重置(与通宵任务书一致)。
