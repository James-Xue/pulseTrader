# pulseTrader 模拟下单策略摘要

> 对象：`pulseTrader` 仓库中 `apps/pulsetrader_ui` 的「模拟gate系统」纸面交易链路。
> 基线：2026-11-10 工作区代码（含未提交改动）。**全程只在本地记账，不向交易所发送任何下单请求。**
> 已提交 HEAD `9790b85` 的信号是 EMA 五周期共振，与当前工作区不同，见第 9 节。
> 完整说明见 `docs/模拟下单策略.md`；本文为供模型分析的精简版。

## 1. 市场与运行方式

| 项 | 内容 |
|---|---|
| 品种 | XAUUSD（Gate TradFi 黄金 CFD），1 手 = 100 盎司 |
| 行情 | Gate REST `getCfdTicker("XAUUSD")`，轮询约 1 秒（REST 往返 1–2 秒） |
| 账户 | 本地模拟账户，按 API Key 隔离，余额手动设置 |
| 持仓 | 可多笔、多方向并存，无数量上限 |
| 落盘 | `data/sim_account.json`（余额+持仓）、`data/sim_orders.db`（订单与止损历史） |

每轮轮询顺序：取价 → 聚合 K 线 → 更新 SuperTrend → 检测 1m 翻转 → 生成开仓决策 → 处理开仓 → 结算已有持仓 TP/SL → 移动止损 → 刷新界面。

## 2. 信号：1 分钟 SuperTrend 方向翻转

**多周期结构**：同时维护 10s / 1m / 15m / 30m 四个周期，每个周期独立 K 线与独立 SuperTrend 实例；回填 500 根，最多保留 500 根。**只有 1m 周期产生开仓信号**，其余周期仅用于日志趋势读数。

**指标参数**：ATR 周期 10，ATR 倍数 3.0（未暴露到界面）。最少 11 根 K 线开始计算。

**算法**：

```
TR  = max(High−Low, |High−prevClose|, |Low−prevClose|)
ATR = 最近 10 根 TR 的简单平均
mid = (High+Low)/2
基础上轨 = mid + 3.0×ATR
基础下轨 = mid − 3.0×ATR

最终上轨 = 基础上轨 < 前值 或 前收 > 前值 ? 基础上轨 : 前值
最终下轨 = 基础下轨 > 前值 或 前收 < 前值 ? 基础下轨 : 前值

多头且 close ≥ 最终下轨 → 保持多头，线 = 最终下轨
空头且 close ≤ 最终上轨 → 保持空头，线 = 最终上轨
多头且 close < 最终下轨 → 翻空
空头且 close > 最终上轨 → 翻多
```

首根 K 线按 `close ≥ mid` 推断方向。

**触发**：

| 事件 | 动作 |
|---|---|
| 1m 由空翻多 | 开多 |
| 1m 由多翻空 | 开空 |

**关键语义**：每轮轮询都用**当前未闭合 K 线**评估并提交状态，因此翻转可在 K 线内发生，响应粒度约 1 秒，不是收盘确认。

**置信度**：`confidence = clamp(|price − SuperTrend线| / ATR, 0, 1)` 会计算，但启动器**不据此过滤**，默认阈值 0.6 实际不生效。

## 3. 开仓规则

- 开仓价 = 当前轮询到的 `last_price`。
- 止盈止损为**固定点数**，默认各 5.0 点：

```
多单：TP = entry + tpPoints,  SL = entry − slPoints
空单：TP = entry − tpPoints,  SL = entry + slPoints
```

- 前置校验：账户存在、手数>0、价格>0、杠杆≥1、TP/SL 必须同时存在且方向正确、可用余额 ≥ 保证金+手续费。
- 过滤条件：

| 过滤 | 行为 |
|---|---|
| 信号冷却 | 两次开仓信号间隔 ≥ `cooldown`（默认 60 秒）；冷却期内翻转只提示，**不排队**，冷却后需新翻转 |
| 休市暂停 | `status != open` 时不评估、不开仓、不结算，轮询降为 60 秒 |
| 开市保护 | 观察到「休市→开市」后前 `openProtectMin`（默认 10）分钟拦截开仓；启动时市场已开则不启用 |
| 置信度/趋势强度 | 无 |
| 最大持仓 / 日内亏损限制 | 无 |

## 4. 保证金、手续费与盈亏

```
名义价值 = 手数 × 100 × 开仓价
保证金   = 名义价值 / 杠杆
手续费   = 手数 × 6 USDT   （仅多单，开仓收一次；空单 0）

开仓：可用余额 −= 保证金 + 手续费
平仓：可用余额 += 保证金 + 已实现盈亏
```

```
多单 PnL = (平仓价 − 开仓价) × 手数 × 100
空单 PnL = (开仓价 − 平仓价) × 手数 × 100
```

示例：0.01 手、4000 开仓、100 倍杠杆 → 名义 4000、保证金 40 USDT、多单手续费 0.06 USDT、价格每变动 1 USD 盈亏 1 USDT。

## 5. 平仓规则

每轮 tick 按开仓顺序逐笔检查：

```
多单：price ≥ TP → 按 TP 价平仓（优先）；price ≤ SL → 按 SL 价平仓
空单：price ≤ TP → 按 TP 价平仓（优先）；price ≥ SL → 按 SL 价平仓
```

- **成交价 = 触发价**，不模拟滑点。
- 平仓不收费；浮盈亏不落账。
- 每笔独立结算，互不影响。
- 休市不结算；重新开市首个 tick 才处理，仍按 TP/SL 触发价成交，**不按跳空后的实际价格**。
- 同一轮中，开仓决策先于结算执行。

## 6. 移动止盈止损

结算之后每个 tick 对全部持仓执行，**只向有利方向移动**：

```
多单：newTP = max(旧TP, price + tpPoints)
      newSL = max(旧SL, price − slPoints)

空单：newTP = min(旧TP, price − tpPoints)
      newSL = min(旧SL, price + slPoints)
```

- 多单要求 `newTP > newSL`，空单 `newTP < newSL`；退化则保留原值不动。
- 仅实际变化才写账户，并向 `order_stops` 追加一条 `reason=trailing`。
- **行为后果**：TP 跟着价格同向移动，正常回撤很难触及 TP；实际退出以移动止损为主。固定止盈通常只在单轮轮询内价格跳涨超过 `tpPoints` 时才命中。

## 7. 持久化与订单分析

**`sim_account.json`**：按 API Key 保存 `balance_usdt` 和持仓数组（含开仓价、TP/SL、保证金、手续费、杠杆、开仓时间）。写文件用「临时文件+rename」。修改余额**保留现有持仓**。

**`sim_orders.db`**：

- `orders`：每笔开仓一行，记录方向、手数、开仓价、初始 TP/SL、杠杆、保证金、手续费、状态、平仓价、已实现盈亏。
- `order_stops`：每次 TP/SL 变化一行，原因 `open` / `trailing`。

**分析指标**：总订单数、已平仓数、持仓中数量、胜率（`PnL>0` 为胜，`PnL≤0` 为负）、总已实现盈亏、TP/SL 平仓笔数、多空分别统计。平仓原因用容差 0.005 比对最终 TP/SL 推断。

## 9. 版本差异（重要）

已提交 HEAD `9790b85` 的模拟盘信号是 **EMA 五周期共振**，当前工作区未提交改动将其替换为 SuperTrend：

| 维度 | 当前工作区 | HEAD `9790b85` |
|---|---|---|
| 信号 | 1m SuperTrend 翻转 | EMA 7/14/30/60/200 严格全排列共振 |
| 方向 | 多空都做 | **只做多** |
| 触发 | 方向翻转 | 共振状态迁入多头时触发，持续期不重发 |
| TP/SL | 固定点数（默认 5.0） | `entry ± mult × ATR14` |
| 移动止损 | 固定点数 | 同一 ATR 包络 |
| 预热 | 11 根 K 线 | 201 根（1m） |

两者共用同一套账户、保证金/手续费、结算、移动止损与持久化逻辑，**差别仅在信号生成层**。仓库另有独立回测撮合器（历史 K 线重放、无保证金/TP/SL），不属于本链路。

## 10. 已知简化与偏差（分析时需考虑）

1. 无滑点、无点差、无隔夜利息；开平仓均按理想价格成交。
2. 跳空处理偏乐观：越过 SL 仍按 SL 价成交。
3. TP 优先于 SL 判断。
4. 无持仓上限，同方向可无限加仓。
5. 无风控层：未接入 RiskManager、回撤保护、下单频率限制、日亏损上限。
6. 移动止盈「追着价格跑」，实际以移动止损退出为主。
7. 修改余额不清仓，易误认为已重置。
8. 胜率口径把 `PnL=0` 计为负；分母只含已平仓订单。
9. 时间戳口径不一致：价格面板用 UTC+8，订单库用本机本地时间。
10. SQLite 写入失败不影响交易，订单历史可能缺失。
11. 界面文案与头文件注释滞后：参数分组仍写「五期EMA共振 + ATR止盈止损包络」，适配器注释仍写 ATR 与「只做多」。
12. 模拟链路只发 GET；真实写操作仅存在于「动态止盈止损」和「自动跟随真实持仓」两个入口，默认关闭。
