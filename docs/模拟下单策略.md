# pulseTrader 模拟下单（纸面交易）策略说明

> 文档基线：2026-11-10 仓库工作区代码（含未提交改动）。
> 已提交 HEAD `9790b85` 的模拟盘信号策略是 **五周期 EMA 共振**；工作区未提交改动将其替换为 **1m SuperTrend 翻转**，差异见 §4.6。
> 适用范围：`apps/pulsetrader_ui` 中的「模拟gate系统」启动器及其纸面交易链路。
> 本文只描述**模拟下单**；真实 CFD 下单/改单不在此链路内（文末单独区分）。

---

## 1. 一句话总结

启动器每秒轮询 Gate TradFi 的 XAUUSD 价格，把 tick 聚合成 10s / 1m / 15m / 30m 四个周期的 K 线，用 **1 分钟 SuperTrend 的方向翻转**作为开仓信号，在本地模拟账户上按真实 CFD 的保证金/手续费模型开多或开空，随后逐 tick 检查 TP/SL、执行只向有利方向移动的移动止盈止损，并把订单生命周期写入 SQLite 供事后分析。**全程不向交易所发送任何下单请求。**

> 注：上面描述的是当前工作区版本。已提交 HEAD `9790b85` 用的是 **五周期 EMA(7/14/30/60/200) 共振 + ATR 包络**，且只做多；两者的差异与 EMA 相关代码见 §4.6。

## 2. 系统定位与边界

| 项 | 说明 |
|---|---|
| 交易品种 | XAUUSD（Gate TradFi 黄金 CFD），合约 1 手 = 100 盎司 |
| 行情来源 | Gate REST：`getCfdTicker("XAUUSD")`，轮询间隔约 1 秒（REST 往返通常 1–2 秒） |
| 信号来源 | 当前工作区：`SuperTrendScalper`；已提交 HEAD：`EmaResonanceScalper`（见 §4.6） |

| 持仓 | 可同时持有多笔、多方向；无最大持仓数限制 |
| 数据落盘 | `data/sim_account.json`（余额 + 持仓）、`data/sim_orders.db`（订单与止损历史） |
| 运行位置 | 轮询在独立线程，模拟开/平仓与界面刷新在 UI 线程 |

## 3. 总体流程

```
启动引擎
   │
   ├─ 回填 4 个周期各 500 根 K 线（REST，失败则靠实时 tick 自然预热）
   │
   └─ 每 ~1 秒循环：
        ① GET XAUUSD ticker → last_price / status
        ② 把 tick 聚合进 10s/1m/15m/30m 当前 K 线
        ③ 每个周期跑 SuperTrend，记录方向
        ④ 1m 方向翻转？──否──> 继续
           │是
           ├─ 冷却中？──是──> 只提示，不开仓
           ├─ 开市保护期？──是──> 拦截开仓
           └─ 生成开仓决策（entry / TP / SL）
        ⑤ UI 线程 handleDecision → SimTradeEngine.openLong / openShort
        ⑥ settleSimPositions：逐 tick 检查 TP/SL，触发则按触发价平仓
        ⑦ applyTrailingStops：只向有利方向移动 TP/SL
        ⑧ 刷新余额、浮动权益、持仓显示
```

对应代码：`MainWindow.cpp:769`（轮询线程）、`MainWindow.cpp:1409`（`onPollResult`）。

## 4. 信号策略：1 分钟 SuperTrend 翻转

### 4.1 多周期结构

`EngineStrategyAdapter` 固定维护四个周期，每个周期有**独立的 K 线序列和独立的 SuperTrend 实例**：

| 周期 | 用途 |
|---|---|
| 10s | 仅用于日志里的趋势读数 |
| **1m** | **唯一产生开仓信号的周期** |
| 15m | 仅用于日志里的趋势读数 |
| 30m | 仅用于日志里的趋势读数 |

- 回填：`getCfdKlines("XAUUSD", 500, 周期标签)`，每个周期最多保留 500 根。
- 最少 K 线：`period + 1 = 11` 根（`kMinCandles = 11`）。
- 若回填失败，1m 周期约 11 分钟后可自然预热完成；10s 约 2 分钟，15m/30m 约 3–6 小时。
- 每次轮询都会用**当前未闭合 K 线**调用 `evaluateState()` 并提交滚动状态，因此方向翻转是按 tick 粒度（约 1 秒）检测的，不等 K 线收盘。

代码：`EngineStrategyAdapter.cpp:126`（周期定义）、`:143`（回填）、`:183`（`onTick`）、`:257`（1m 信号）。

### 4.2 SuperTrend 指标算法

参数使用 `StrategyParams` 默认值，启动器没有暴露这两个参数到界面：

| 参数 | 默认值 |
|---|---|
| `supertrend_period`（ATR 周期） | 10 |
| `supertrend_multiplier`（ATR 倍数） | 3.0 |

计算步骤：

```
TR  = max(High − Low, |High − prevClose|, |Low − prevClose|)
ATR = 最近 10 根 TR 的简单平均

mid           = (High + Low) / 2
basic_upper   = mid + 3.0 × ATR
basic_lower   = mid − 3.0 × ATR

final_upper:  basic_upper < prev_upper 或 prev_close > prev_upper ? basic_upper : prev_upper
final_lower:  basic_lower > prev_lower 或 prev_close < prev_lower ? basic_lower : prev_lower

当前方向 / SuperTrend 线：
  多头且 close ≥ final_lower  → 保持多头，线 = final_lower
  空头且 close ≤ final_upper  → 保持空头，线 = final_upper
  多头且 close < final_lower  → 翻空，线 = final_upper
  空头且 close > final_upper  → 翻多，线 = final_lower
```

首次计算时按 `close >= mid` 推断方向。

代码：`SuperTrendScalper.cpp:165`（`evaluateState`）、`StrategyParams.hpp:65`。

### 4.3 入场触发

| 事件 | 信号 |
|---|---|
| 1m 周期由空翻多 | 开多（`side = "long"`） |
| 1m 周期由多翻空 | 开空（`side = "short"`） |

- 开仓价 `entryPrice` = 当前轮询到的 `last_price`。
- 止盈止损为**固定点数包络**，不是 ATR 包络：

```
多头：TP = entry + tpPoints     SL = entry − slPoints
空头：TP = entry − tpPoints     SL = entry + slPoints
```

- `tpPoints` / `slPoints` 来自界面「止盈点数 / 止损点数」，默认均为 **5.0**。
- `confidence = clamp(|price − SuperTrend| / ATR, 0, 1)` 会计算并随决策返回，但**启动器不据此过滤**，`min_confidence` 默认值 0.6 在本链路中未生效。
- 同一轮只有 1m 周期能产生决策；10s/15m/30m 翻转只写入日志趋势读数。

### 4.4 过滤条件

| 过滤 | 行为 |
|---|---|
| **信号冷却** | 两次开仓信号之间至少间隔 `cooldown`（默认 60 秒）。冷却期内出现的新翻转只提示「信号冷却中」，**不排队**，冷却结束后需要新的一次翻转。 |
| **休市暂停** | ticker 的 `status != open` 时不评估、不开仓、不结算，轮询降为 60 秒。 |
| **开市保护** | 观察到「休市 → 开市」切换后，前 `openProtectMin`（默认 10）分钟内拦截开仓；评估继续运行以保持 K 线连续。若启动时市场已开，则不启用该保护窗口。 |
| 趋势强度 | 无额外过滤 |
| 最小置信度 | 未启用 |
| 最大持仓数 | 无限制 |
| 日内亏损限制 | 无 |

代码：`EngineStrategyAdapter.cpp:259`（冷却）、`MainWindow.cpp:837`（休市识别）、`:952`（开市保护）。

### 4.5 为什么日志里的周期读数会频繁变化

SuperTrend 每次 `onTick` 都会提交状态，而 1m K 线在整分钟内持续被 tick 更新（最高/最低/收盘价），所以 1m 方向可能在 K 线未收盘时翻转。这是有意为之：启动器追求约 1 秒级的响应，而不是标准「收盘确认」语义。

### 4.6 EMA 相关实现与版本差异

仓库里确实有 EMA 数据/策略实现，而且**已提交版本（HEAD `9790b85`）的模拟盘用的就是 EMA 共振**。当前工作区的未提交改动把它替换成了 SuperTrend。三处 EMA 实现如下：

| 实现 | 位置 | 作用 | 当前是否驱动模拟下单 |
|---|---|---|---|
| `EmaResonanceScalper` | `src/strategy/scalping/` | 五周期 EMA 7/14/30/60/200 严格全排列共振；共振状态迁移时触发 | 已提交 HEAD 中**是**；当前工作区**否**（被 SuperTrend 替换） |
| `MultiTimeframeEma` | `apps/pulsetrader_ui/` | 7 条 EMA `{7,14,31,60,90,120,180}` × 7 个周期 `{1m,3m,5m,10m,15m,30m,60m}` 的参考面板数据 | 否；面板已从窗口移除，类与单测保留 |
| `GoldStrategyEngine` v1 | `apps/pulsetrader_ui/` | EMA 10/30 趋势 + tick 波幅包络，只做多 | 否；只借用其 `Params` 参数块 |

#### 已提交 HEAD 的模拟盘信号（EMA 共振）

- 适配器只聚合 **1m K 线**，回填 500 根，预热需要 **201 根**。
- 指标：EMA 7 / 14 / 30 / 60 / 200（`res_ema_p1..p5` 默认值）。
- 多头共振：`EMA7 > EMA14 > EMA30 > EMA60 > EMA200`。
- 入场：共振状态由 `mixed`/空头**迁入多头共振**时开多；共振持续期间不重发。
- **只做多**，空头共振不产生模拟空单。
- TP/SL：`entry ± mult × ATR14`（ATR14 来自 1m K 线），不是固定点数。
- 移动止损：用同一 ATR 包络 `suggestStops()`。
- 冷却在策略评估之前检查。

代码：`src/strategy/scalping/EmaResonanceScalper.cpp:36`、`docs/strategies/ema-resonance-scalper.md`。

#### 当前工作区（未提交）的模拟盘信号

- 四周期 SuperTrend：10s / 1m / 15m / 30m。
- 1m 翻多开多、翻空开空（**多空都做**）。
- TP/SL 为固定点数（默认 5.0），移动止损也用固定点数。
- 详见本文 §4.1–§4.4。

#### `MultiTimeframeEma` 是什么

它是一个**纯展示用的 EMA 参考面板数据类**（不是下单策略）：

- EMA 周期：`{7, 14, 31, 60, 90, 120, 180}`；
- 周期：`{1m, 3m, 5m, 10m, 15m, 30m, 60m}`，其中 `60m` 映射到 Gate 的 `1h` kline_type；
- 每个周期回填 500 根 K 线，少于 180 根时标记为预热中；
- 快照只用于界面显示，注释明确写着 "Display-only for now … also available for future strategy logic"；
- 该面板已从主窗口移除（代码注释记录为 2026-09-23，位置被美元指数面板取代），但 `MultiTimeframeEma` 类和单测仍保留在 `pulse_ui` 中，当前轮询链路**没有调用它**。

代码：`apps/pulsetrader_ui/MultiTimeframeEma.hpp:1`、`MultiTimeframeEma.cpp:142`。

#### 为什么容易记成 EMA

以下文案都是 EMA 版本的遗留，当前实现没有同步更新：

- 参数分组标题仍写「五期EMA共振 + ATR止盈止损包络」；
- `EngineStrategyAdapter.hpp` 顶部注释仍写「TP/SL = entry ± mult × ATR」；
- 同一处注释还写「Only long (Buy) entries are surfaced」，但当前实现已支持空单。

因此：**看 HEAD 代码或界面文案会认为是 EMA 共振；看当前工作区实现则是 SuperTrend 翻转。** 两者共用同一套模拟账户、保证金/手续费、TP/SL 结算、移动止损、SQLite 与订单分析逻辑，差别只在信号生成层。

#### 引擎侧仍然可用

`EmaResonanceScalper` 仍注册在 `StrategyRegistry`（`src/strategy/StrategyRegistry.cpp:81`），可通过 `trading.toml` 的 `[[strategy.instances]]` 启用；`trading.toml.example` 第 144–160 行有完整示例。注意这是 **pulseTrader 引擎**的策略实例，不是启动器的模拟盘链路。

## 5. 模拟下单与账户模型

### 5.1 开仓前置校验

`SimTradeEngine::openLong / openShort` 会依次校验：

1. 模拟账户存在（按 API Key 查询）；
2. 手数 > 0、价格 > 0；
3. 杠杆 ≥ 1；
4. TP 与 SL **必须同时存在**（模拟真实 CFD「开仓单必须带止盈止损」的规则）；
5. 方向正确：
   - 多单：TP > entry > SL；
   - 空单：TP < entry < SL；
6. 可用余额 ≥ 保证金 + 手续费。

任一失败都会返回中文错误，不产生持仓。

### 5.2 保证金、手续费与盈亏

```
名义价值 = 手数 × 100 盎司/手 × 开仓价
保证金   = 名义价值 / 杠杆
手续费   = 手数 × 6 USDT        （仅多单，开仓时收一次）
空单手续费 = 0                    （真实 CFD 卖出侧免佣）

开仓时：可用余额 −= 保证金 + 手续费
平仓时：可用余额 += 保证金 + 已实现盈亏
```

盈亏公式：

```
多单 PnL = (平仓价 − 开仓价) × 手数 × 100
空单 PnL = (开仓价 − 平仓价) × 手数 × 100
```

示例（0.01 手、4000 开仓、100 倍杠杆）：

| 项 | 数值 |
|---|---|
| 名义价值 | 0.01 × 100 × 4000 = 4000 USDT |
| 保证金 | 40 USDT |
| 多单手续费 | 0.06 USDT |
| 价格每变动 1 USD | 盈亏 1 USDT |

> 代码中金额单位写作 USDT，但 CFD 账户实际以 USD 计价；本模拟链路按 1:1 处理。

### 5.3 订单号

格式：`SIM-<Unix 毫秒时间戳>-<进程内自增序号>`

例：`SIM-1700000000000-0`。时间戳保证跨进程启动不重复，自增序号保证同一毫秒内不重复。

代码：`SimTradeEngine.cpp:29`（`openPosition`）、`:135`（`openLong`）、`:174`（`openShort`）。

## 6. 平仓结算规则

每个轮询 tick，在开仓决策处理完之后执行 `checkAndClose`：

```
按持仓开仓顺序逐笔检查：

多单：
  price ≥ TP  →  以 TP 价平仓，原因 "TP"     （优先判断）
  price ≤ SL  →  以 SL 价平仓，原因 "SL"

空单：
  price ≤ TP  →  以 TP 价平仓，原因 "TP"     （优先判断）
  price ≥ SL  →  以 SL 价平仓，原因 "SL"
```

- **成交价 = 触发价**（TP 触发的按 TP 价成交，SL 触发的按 SL 价成交）。
- 浮盈浮亏不落账；只有平仓时结算已实现盈亏。
- 平仓不收费。
- 多笔持仓独立结算，互不影响。
- 休市期间不结算；重新开市后的第一个 tick 才会处理，并按 TP/SL 的触发价成交（**不会按跳空后的实际价格成交**）。

代码：`SimTradeEngine.cpp:212`（`checkAndClose`）、`MainWindow.cpp:1530`（`settleSimPositions`）。

## 7. 移动止盈止损（Trailing）

结算之后，每个 tick 对全部持仓执行 `updateStops`。规则：**止损/止盈只向有利方向移动，绝不扩大风险**。

```
多单：newTP = max(旧TP, price + tpPoints)
      newSL = max(旧SL, price − slPoints)
      只向上移动

空单：newTP = min(旧TP, price − tpPoints)
      newSL = min(旧SL, price + slPoints)
      只向下移动
```

额外约束：

- 多单要求 `newTP > newSL`，空单要求 `newTP < newSL`；若计算出的组合退化，则保留原 TP/SL 不动。
- 只有实际发生变化才写入账户，并向 `order_stops` 表追加一条 `reason = "trailing"` 的记录。
- 使用的 `tpPoints` / `slPoints` 与开仓时相同，默认 5.0 点。

### 行为特征（重要）

由于 TP 也跟着价格同向移动：

- 多单上涨时，TP 始终保持在「当前价 + tpPoints」之上，正常回撤很难触及 TP；
- 多单下跌时，TP/SL 都不动，最终通常由 `price − slPoints` 形成的移动止损触发平仓；
- 因此实际退出**以移动止损为主**，固定止盈通常只在单次轮询间隔内价格快速冲高超过 `tpPoints` 时被触发。

代码：`SimTradeEngine.cpp:300`（`updateStops`）、`MainWindow.cpp:1455`（`applyTrailingStops`）。

## 8. 持久化

### 8.1 模拟账户：`data/sim_account.json`

路径解析顺序：

1. 进程工作目录下的 `data/sim_account.json`（从仓库根目录启动时）；
2. 若工作目录没有 `data/`，退回可执行文件目录下的 `data/sim_account.json`。

结构：

```json
{
  "accounts": {
    "<api key>": {
      "balance_usdt": 100.0,
      "positions": [
        {
          "id": "SIM-1700000000000-0",
          "side": "long",
          "volume": 0.01,
          "entry": 4000.0,
          "tp": 4005.0,
          "sl": 3995.0,
          "margin": 40.0,
          "fee": 0.06,
          "leverage": 100.0,
          "opened_at_ms": 1700000000000
        }
      ],
      "updated_at": "2026-09-03 18:22:12"
    }
  }
}
```

- 账户以 **API Key** 为身份；同一 Key 重新登录会恢复同一余额和持仓。
- 写文件采用「临时文件 + rename」的近似原子写；Windows 下会先删除目标文件再重命名。
- 「模拟账户」按钮只修改余额，**保留现有持仓**；要彻底重置需删除该 JSON 或先平掉持仓。

### 8.2 订单库：`data/sim_orders.db`（SQLite / QSQLITE）

| 表 | 内容 |
|---|---|
| `orders` | 每笔开仓一行：`order_id`、`api_key`、方向、品种、手数、开仓价、开仓时 TP/SL、杠杆、保证金、手续费、状态（open/closed）、开平时间、平仓价、已实现盈亏 |
| `order_stops` | 每次 TP/SL 变化一行：`order_id`、时间、TP、SL、更新时价格、原因（`open` / `trailing`） |

- 开仓时同时写入 `orders` 和一条 `order_stops`（`reason = "open"`，`price = entry`）。
- 平仓时更新 `orders.status = 'closed'`、`exit_price`、`realized_pnl`、`closed_at`。
- SQLite 或驱动不可用时，订单历史不落库，但**模拟交易本身继续运行**。

代码：`SimOrderDb.cpp:59`（建表）、`:116`（`insertOrder`）、`:153`（`closeOrder`）、`:167`（`insertStopUpdate`）。

## 9. 交易后分析

点击「订单分析」时，`SimOrderAnalyzer::analyze(apiKey)` 从 SQLite 读取并汇总：

**单笔订单**

- 开仓时间、方向、开仓价；
- 初始 TP/SL；
- 最终 TP/SL（取 `order_stops` 最后一行）；
- 移动止损次数（`order_stops` 行数 − 1，首行是开仓附件）；
- 平仓原因：把平仓价与最终 TP/SL 比较，容差 0.005；匹配不上时按方向兜底推断；
- 平仓价与已实现盈亏。

**汇总指标**

- 总订单数、已平仓数、持仓中数量；
- 胜率 = 盈利笔数 / 已平仓笔数（`PnL > 0` 记为胜，`PnL ≤ 0` 记为负）；
- 总已实现盈亏；
- TP 平仓笔数、SL 平仓笔数；
- 多单/空单各自笔数与盈亏。

## 11. 行为特征与风险点

1. **无滑点、无点差、无隔夜利息**：开仓按 `last_price`，平仓按 TP/SL 触发价，均不模拟买卖价差与滑点。真实 CFD 的点差和隔夜库存费未计入。
2. **跳空处理偏乐观**：休市或长时间停轮询后，若价格已越过 SL，重新开市的首个 tick 仍按 SL 价成交，不会按跳空后的更差价格成交。
3. **TP 优先于 SL**：同一 tick 同时满足时先判 TP。正常情况下多空两侧不会同时满足，但逻辑顺序值得知悉。
4. **无持仓上限**：冷却只限制信号频率，不限制持仓数量；同一方向可不断加仓，余额允许即可。
5. **无风控层**：该模拟链路没有接入 `RiskManager`、`DrawdownGuard`、`OrderRateLimiter`，也没有每日亏损上限。
6. **移动止盈会「追着价格跑」**：见 §7，实际退出以移动止损为主。
7. **改余额不清仓**：「模拟账户」按钮保存新余额时会保留现有持仓，容易误以为重置了账户。
8. **盈亏口径**：`PnL = 0` 被统计为负；胜率分母只含已平仓订单。
9. **界面文案/头文件注释滞后于实现**（详见 §4.6）：
   - 参数分组标题仍写「五期EMA共振 + ATR止盈止损包络」；
   - `EngineStrategyAdapter.hpp` 顶部注释仍提到「TP/SL = entry ± mult × ATR」；
   - 同一处注释还写「Only long (Buy) entries are surfaced」，但当前实现已支持空单；
   - 当前工作区实际是 **1m SuperTrend 翻转 + 固定点数 TP/SL**。
10. **EMA 相关代码的当前归属**：`EmaResonanceScalper` 在已提交 HEAD 中驱动模拟盘，当前工作区已被 SuperTrend 替换；`MultiTimeframeEma` 是展示用面板数据且已从窗口移除；`GoldStrategyEngine` 仅借用其 `Params`。详见 §4.6。
11. **时间戳口径不一致**：价格面板使用固定 UTC+8 北京时间；订单库 `openedAt/closedAt` 使用本机本地时间。
12. **数据库写入失败不影响交易**：订单历史可能缺失，但账户与持仓仍会正常更新。
13. **模拟链路不发真实订单**：轮询只调用 GET（ticker / klines / assets）。真实写操作只存在于「自动跟随真实持仓」与「动态止盈止损」两个入口，且需要 API Key 具备 CFD 读写权限。

## 12. 与「真实持仓」功能的分界

启动器里有两类完全不同的操作，切勿混淆：

| 功能 | 作用对象 | 是否真实下单/改单 | 默认状态 |
|---|---|---|---|
| 启动引擎 + 自动开仓/平仓 | 本地 `sim_account.json` | 否 | 启动引擎后自动 |
| 订单分析 | 本地 `sim_orders.db` | 否 | 手动点击 |
| 动态止盈止损 | **交易所真实 CFD 持仓** | 是（`putCfdPositionModify`） | 手动点击 + 二次确认 |
| 自动跟随真实持仓 | **交易所真实 CFD 持仓** | 是（按间隔 + 价格阈值自动 PUT） | 默认关闭 |

- 真实改单需要该 API Key 对 `tradfi` 具备读写权限；只读 Key 会被拦截并提示。
- 真实持仓的止损锚定**开仓价**（`entry ± points`），与模拟持仓的移动止损逻辑不同。

## 13. 与回测引擎的区别

仓库里另有一套回测撮合器 `BacktestAccount`（`src/backtest/`），与本模拟盘不是同一条链路：

| 维度 | 启动器模拟盘 | 回测引擎 |
|---|---|---|
| 数据 | 实时 REST ticker 轮询 | 历史 K 线重放 |
| 信号 | 1m SuperTrend 方向翻转 | 任意注册策略 |
| 成交 | 开仓按当前价；平仓按 TP/SL 触发价 | 信号价立即成交（K 线收盘价），收 taker 手续费 |
| 保证金/杠杆 | 有 | 无（按数量与 quanto 计算） |
| TP/SL / 移动止损 | 有 | 无 |
| 持仓约束 | 无上限 | `Flip` / `Independent` 两种模式 |
| 输出 | JSON + SQLite + 界面分析 | 控制台表格 / JSON 报告 |

## 15. 附：按代码复现一次完整交易

以默认参数、100 倍杠杆、余额 100 USDT 为例：

1. 1m SuperTrend 由空翻多，当前价 4000.00。
2. 决策：`long`，`entry = 4000.00`，`TP = 4005.00`，`SL = 3995.00`。
3. 开仓校验通过：
   - 保证金 = 0.01 × 100 × 4000 / 100 = **40.00 USDT**
   - 手续费 = 0.01 × 6 = **0.06 USDT**
   - 可用余额变为 **59.94 USDT**
4. 持仓写入 JSON；订单写入 SQLite（`status = open`，并追加 `open` 止损记录）。
5. 价格逐 tick 上涨到 4010（每个轮询间隔的涨幅都小于 5 点，因此 4005 的初始 TP 不会先触发）：
   - 移动止损：`TP = max(4005, 4015) = 4015`，`SL = max(3995, 4005) = 4005`。
   - 若价格是**单轮直接跳到 4010**，则同一轮的结算会先命中初始 TP 4005，以 4005 平仓（盈亏 +5），不会走到移动止损。
6. 价格回落到 4005：
   - 触发 SL，按 4005 平仓；
   - PnL = (4005 − 4000) × 0.01 × 100 = **+5.00 USDT**；
   - 余额 = 59.94 + 40.00 + 5.00 = **104.94 USDT**。
7. 订单状态改为 `closed`，分析页显示：1 笔已平、TP 0 笔、SL 1 笔、胜率 100%、总盈亏 +5.00。
